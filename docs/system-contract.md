# AI System Contract — LoL ontology recommendation prototype

상태: 2026-10-08 로컬 프로토타입 구현. 출시 승인 문서가 아니다. 구현·검증 상태는 `implementation-status.md`에 기록한다.

확정 1차 범위: 수동 밴픽, 선호도·자가평가 숙련도, 픽 추천, 픽 기반 아이템 초안. OP.GG MCP의 티어·패치 조회를 연결하되 실제 응답 검증 전에는 메타 통계를 추천 점수에 자동 반영하지 않는다. 실시간 기능은 후속 범위다.

## 목적과 영향

- 사용자 문제: 조합·챔피언 숙련·구매 경로를 고려한 선택 이유를 이해하기 어렵다.
- 성공 행동: 유효한 후보 여러 개와 근거·조건·불확실성을 확인하고 사용자가 결정한다.
- 틀린 응답의 피해: 불리한 픽/빌드, 잘못된 학습, 플레이 중 방해.
- 금지 행동: 자동 픽/밴/구매, 숨겨진 신원 추적, 메모리 접근, 출처 없는 효과 확정.

## 입력과 문맥

- 출처: Data Dragon, 인증 Riot 경기 데이터, 검토된 의미 주석, 사용자 입력. 로컬 데이터 연동은 별도 검증.
- 권한·보존: API 키는 서버에만, 로컬 인증은 기기 내 유지. 사용자별 원시 데이터 수집 범위·동의·보존 기간은 공개 서비스 전에 결정 필요.
- 신선도: 패치·큐·시점 명시. 미지원 패치는 제한 모드. 누락과 실제 0 구분.
- 버전: 데이터·온톨로지·규칙·통계 모델·설명 템플릿을 독립 버전 관리.
- LLM: 의미 주석 초안에 선택적으로 사용. 모델·프롬프트는 도입 시 결정 필요. 런타임 추천에 필수 아님.

## 결정과 권한

- 모델 범위: 후보 랭킹, 선택적 설명 초안.
- 최종 결정: 플레이어. 코드가 후보의 패치·구매·선택 제약을 검사.
- 신뢰 부족: 통계 없음 표시, 검토된 규칙만 사용 또는 추천 보류.
- 읽기: 정적·경기 API, 승인 범위 내 로컬 읽기 어댑터.
- 쓰기: 앱 자체 저장소만. 게임 클라이언트 행동 API는 사용하지 않음.
- 사람 결정: 의미 주석 검토, 공개 범위, 실시간 화면의 정책 적합성 확인.

## 성공과 실패

- 품질 목표: 고정 평가셋에서 유효하지 않은 후보 0건. 통계 기준선 대비 품질 차이는 측정 후 판단.
- 설명 목표: 모든 효과 주장·패치·후보에 추적 가능한 근거. 확인되지 않은 승률 향상 표시 금지.
- 지연 목표 제안: 입력 수신 후 랭킹 p95 300ms 이내. 로컬 관측 간격·UI 전달 지연은 별도 측정. 아직 벤치마크 없음.
- 비용 목표: 실시간 상태 변경마다 LLM 호출 없음. 수집·저장 예산은 표본 규모 결정 후 산정.
- 실패 UX: 연결 끊김·오래된 상태 표시, 수동 입력/정적 비교로 전환.
- 롤백: 이전 검증 데이터·규칙 버전 유지. 현재 패치와 불일치하면 이전 것을 현행 추천으로 제시하지 않음.
- 검토 담당: 초기에는 프로젝트 개발자. 외부 전문가와 검토 응답 시간은 결정 필요.

## 운영

- 평가: 시간 분할, 경기 단위 분리, 온톨로지/통계 ablation, 전문가 후보·설명 평가.
- 트레이스: 최소 상태 요약, 관측 시각, 데이터·규칙 버전, 추천 근거, 처리 시간. 비밀 인증 정보 로깅 금지.
- 알림: 스키마·패치 변경, 누락 증가, 제약 위반, stale 상태 증가.
- 담당자: 프로젝트 개발자. 공개 서비스 운영 책임자는 출시 전에 지정.
- 재검토: 대상 패치·클라이언트·정책 변경 및 공개 서비스 전.
